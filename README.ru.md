# Classroom CRM

[English version](README.md)

Статическое одностраничное приложение для рабочего кабинета классного руководителя. Приложение моделирует школьные процессы без серверной части: данные, авторизация и бизнес-операции хранятся в `localStorage` браузера.

## Возможности

Приложение поддерживает пять ролей:

- администратор;
- классный руководитель;
- учитель-предметник;
- родитель;
- ученик.

Реализованы управление учётными записями и педагогами, учебные годы и справочники, нагрузка, классы и ученики, журналы, посещаемость и медицинские справки, расписание, родители, собрания, объявления, аналитика и недельный контроль класса.

## Технологии

- HTML5, Tailwind CSS и Vanilla JavaScript с ES-модулями;
- esbuild для сборки приложения;
- Playwright для end-to-end проверки сайта;
- Python, Pytest и Selenium в Docker для проверки учебных задач.

## Структура репозитория

| Каталог | Назначение |
| --- | --- |
| `src/` | Исходный код SPA: представления, роутинг, сервисы и мок-данные. |
| `reference/` | Собранная версия сайта. Генерируется командой сборки; вручную не редактируется. |
| `tests/` | Playwright-спеки, фикстуры, page objects, хелперы и HTTP-сервер. |
| `tasks/` | 32 учебных пакета с описаниями, шаблонами, решениями и вариантами сайта. |
| `tools/task-mutations/` | Конфигурации преднамеренных дефектов для учебных задач. |
| `tools/tests-runner/` | Версионируемый Docker-раннер для Selenium/Pytest-проверки учебных задач. |
| `tools/build-task.mjs` | Собирает эталонный и мутированные варианты учебной задачи. |
| `tools/verify-tasks.mjs` | Обёртка npm-команды для сборки раннера и проверки задач. |
| `deploy/` | Dockerfile, Compose-конфигурации и конфигурация Nginx. |

## Требования

- Node.js 20+;
- Docker Desktop — для проверки учебных задач и запуска в контейнере;
- Python 3 — только для ручной раздачи собранного сайта встроенным HTTP-сервером.

## Установка и локальный запуск

```bash
npm ci
npm run build:site
python -m http.server 8080 -d reference
```

После запуска сайт доступен по адресу `http://127.0.0.1:8080/`. Примеры маршрутов: `/login/`, `/journal/` и `/overview/`.

Результат сборки всегда записывается в `reference/`. После изменения файлов в `src/` перед ручной проверкой или E2E-тестами выполните:

```bash
npm run build:site
```

## Проверка сайта

Playwright автоматически запускает `tests/server.py` и раздаёт актуальную сборку из `reference/`.

```bash
npm test
```

Полный детерминированный прогон рекомендуется выполнять последовательно:

```bash
npm test -- --workers=1 --reporter=line
```

Дополнительные режимы:

```bash
npm run test:headed
npm run test:ui
npm run test:report
```

## Проверка учебных задач

Учебная задача содержит `task.md`, `template.py`, `solution.py`, эталонный сайт в `reference/` и `testcases/`. Каждая конфигурация в `tools/task-mutations/` описывает преднамеренные дефекты и тесты, которые должны на них упасть.

### Проверить все задачи

```bash
npm run test:tasks
```

Команда:

1. собирает локальный образ `auto-tests-runner:latest` из `tools/tests-runner/`;
2. пересобирает эталонный и мутированные варианты всех задач;
3. запускает Selenium/Pytest в Docker для каждого пакета;
4. проверяет, что baseline проходит, а каждый вариант дефекта вызывает ожидаемые падения.

### Быстрая повторная проверка

```bash
npm run test:tasks -- --skip-build
```

Этот режим не пересобирает Docker-образ, `reference/` и `testcases/`. До запуска Docker он сравнивает baseline каждой задачи с текущим `reference/` и требует успешного предыдущего полного прогона всех задач при неизменных исходниках, пакетах задач и конфигурациях мутаций. Иначе команда сразу остановится и попросит выполнить обычный `npm run test:tasks`.

### Проверить одну задачу

```bash
npm run test:tasks -- --task task-14-journal-attendance
```

Для быстрой пересборки без Docker-верификации вызовите сборщик напрямую:

```bash
node tools/build-task.mjs --task task-14-journal-attendance
node tools/build-task.mjs --all
```

Результаты Docker-прогона временно сохраняются в `tasks/<имя-задачи>/results/`. Эти каталоги игнорируются Git и могут быть удалены после анализа.

### Docker-раннер задач

`tools/tests-runner/` намеренно хранится в репозитории, а не только в `docs/`: каталог `docs/` игнорируется Git и не попал бы в клон или поставку проекта. Раннер содержит:

- `Dockerfile` — образ на основе Selenium Chrome;
- `test.sh` — запускает Selenium, HTTP-сервер и Pytest для каждого варианта в `testcases/`;
- `parser.bin` — преобразует JUnit-отчёты в краткие JSON-результаты.

При необходимости образ можно собрать вручную:

```bash
docker build -t auto-tests-runner:latest tools/tests-runner
```

## Запуск в Docker

```bash
docker build -f deploy/Dockerfile -t classroom-crm:local .
docker run --rm -p 8080:80 classroom-crm:local
```

Проверить health endpoint контейнера:

```bash
curl http://127.0.0.1:8080/health
```

Compose-конфигурации находятся в `deploy/`.
