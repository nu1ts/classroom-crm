# Собрания: явка и итоги

## Сайт

«Кабинет классного руководителя» — одностраничное приложение для школы.
Классный руководитель ведёт родительские собрания 7Б, фиксирует явку родителей
после проведения встречи и открывает итоги. Данные хранятся в `localStorage` и
после его очистки восстанавливаются в исходное состояние. Демонстрационная дата
стенда — 28.10.2024.

| Родитель Петровой А. | `petrov@mail.ru` | `Test#2024` |

## Начальные данные

- прошедшее собрание «Организационное собрание начала года: Организация учебного
  года» состоялось 05.09.2024 в 18:30 в кабинете 302;
- у него 28 записей явки: пришли 24 родителя, двое не пришли и у двоих
  уважительная причина;
- ближайшее собрание «Итоги первой четверти 7Б» назначено на 31.10.2024,
  поэтому до его проведения отмечать явку нельзя;
- у Котовой Е. П. исходная отметка «Не пришёл» с причиной «Работает допоздна»,
  у Сидоровой О. Н. — «Уважительная причина» и «Не выходит на связь»;
- Петров С. В. — родитель Петровой Анны; он может видеть приглашение и сведения
  о собраниях своего класса, но не явку других семей и не итоги класса.

## Что нужно реализовать

Реализуйте учёт явки для прошедших собраний и итог по текущим отметкам. Для каждого приглашённого родителя хранится одна запись со статусом и, при неявке, причиной. Будущим собраниям нельзя назначать явку. Родитель видит сведения о собраниях своего класса, но не явку других семей и не общие итоги.

## Проверяемые сценарии

1. `test_mg_07_attendance_values` — у прошедшего собрания открывается форма «Отметка явки на собрание» с 28 строками. В поле «Явка» доступны только «Пришёл», «Не пришёл», «Уважительная причина», а «Да», «Нет» и «Не ответил» отсутствуют. После сохранения повторно открытая форма сохраняет: у Котовой Е. П. «Не пришёл» и «Работает допоздна», у Сидоровой О. Н. «Уважительная причина» и «Не выходит на связь»; счётчик содержит корректное число от 0 до 28.
2. `test_mg_08_absence_reason_required` — у Петрова С. В. значение «Уважительная причина» без примечания не сохраняется: показано «Причина неявки обязательна», поле причины выделено. После ввода «Болезнь ребёнка» запись сохраняется. При смене значения на «Пришёл» оно сохраняется без примечания, а ранее введённый текст причины не удаляется.
3. `test_mg_09_future_attendance_blocked` — у будущего собрания «Итоги первой четверти 7Б» нет действия «Отметить явку». Попытка сохранить отметку через публичный `crmApi` возвращает отказ с сообщением, содержащим «нельзя», и не создаёт записей явки для этого собрания.
4. `test_mg_10_summary_realtime` — итоги прошедшего собрания сначала показывают «24 из 28». После изменения явки Александровой И. А. на «Не пришёл» с причиной «Срочная работа» показывается «23 из 28», а фамилия и причина есть среди непришедших. После возврата значения «Пришёл» итог снова «24 из 28»: он рассчитывается из текущих записей без устаревшего кэша.
5. `test_mg_11_parent_meetings` — родитель Петров С. В. на странице ребёнка видит блок «Собрания класса»: ближайшее собрание «Итоги первой четверти 7Б», дату «31 октября 2024 г.», «Каб. 302», повестку и прошедшее «Организационное собрание начала года». Он не видит явку, кнопки отметки явки и итогов, бейджи явки и сведения о других семьях.
6. `test_mg_13_all_present_counter` — если всем 28 родителям установить «Пришёл» без примечания, сохраняются все 28 записей. После повторного открытия все строки имеют значение «Пришёл», числовой счётчик равен 28, а форма содержит текст «Всего пришли: 28 из 28».

## Особенности автоматической проверки

Проверка будущего собрания дополнительно вызывает публичный `crmApi`: это нужно, чтобы убедиться, что запрет действует не только на кнопке интерфейса, но и в доменной операции. Остальные сценарии выполняются через интерфейс.
