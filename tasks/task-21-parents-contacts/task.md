# Контакты с родителями: история общения

## Назначение

В разделе «Родители» классный руководитель открывает сводку родителя, видит анкетные данные только для чтения, связанных учеников и историю общения. Контакт содержит канал, итог, дату, необязательную привязку к конкретному ученику и отметку о достигнутой договорённости. История должна быть упорядочена от новых записей к старым. Родитель видит только сведения о своём ребёнке и не получает доступ к внутренней истории общения.

Данные стенда хранятся в `localStorage` и восстанавливаются после очистки. Демонстрационная дата — 28.10.2024.

## Исходные данные

- В сводке родителя `pr-27` анкетные данные доступны только для чтения; редактирование телефона в этой сводке не предлагается.
- У Котовой Е. П. (`pr-10`) двое детей: Котов Максим и Котова Дарья; один из них учится в 9В.
- У Сидоровой О. Н. (`pr-27`) в истории есть как минимум две записи: от 26.10.2024 и 18.10.2024.
- Для контактов используются каналы, включая `phone` и `chat`; обязательны родитель, канал и итог контакта. Привязка к ученику необязательна.

## Что нужно реализовать

Реализуйте сводку родителя и историю общения с сохранением обязательных полей, признака договорённости, корректной привязки к ученику и разграничением доступа по ролям.

## Проверяемые сценарии

1. `test_pr_13_summary_read_only` — классный руководитель открывает сводку родителя `pr-27`. На странице есть сообщение «Анкетные данные — только чтение в сводке», а элемента редактирования телефона нет.
2. `test_pr_14_summary_all_children` — в сводке Котовой Е. П. блок «Связанные ученики» содержит Котова Максима, Котову Дарью и указание «9В класс». Дети из другого класса не скрываются.
3. `test_pr_15_contact_agreement` — для `pr-27` создаётся контакт по телефону с итогом «Договорились», датой 28.10.2024, учеником `st-14` и отмеченной договорённостью. Операция успешна, а сохранённый контакт содержит эту отметку.
4. `test_pr_16_contact_required_fields` — создание контакта без канала отклоняется с сообщением о канале; создание контакта с каналом, но с пустым итогом отклоняется с сообщением «Итог». Некорректные контакты не сохраняются.
5. `test_pr_17_contact_without_student` — для Котовой Е. П. создаётся общий контакт через чат с итогом «Общий контакт», датой 28.10.2024 и без ученика. Запись сохраняется только у родителя `pr-10`, а поле ученика остаётся пустым: она не становится записью каждого ребёнка.
6. `test_pr_18_history_order` — в сводке Сидоровой О. Н. история общения содержит минимум две записи; запись от 26.10.2024 отображается раньше записи от 18.10.2024.
7. `test_pr_19_parents_route_denied` — родитель Петров С. В. при прямом переходе на маршрут `/parents/` получает страницу «Доступ ограничен» и не видит содержимое базы «Родители 7Б».
8. `test_pr_20_history_hidden_from_parent` — родитель открывает страницу ребёнка. В ней не отображаются «История общения с родителями» и «Заметки классрука».

## Особенности автоматической проверки

Для сценариев 3–5 автотест вызывает публичные операции `crmApi`, чтобы подготовить контакты с точными значениями. Это требуется для проверки бизнес-инвариантов и не заменяет пользовательский интерфейс. Маршрут и скрытие данных в сценариях 7–8 проверяются через интерфейс.
