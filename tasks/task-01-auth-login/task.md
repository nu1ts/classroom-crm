# Авторизация: вход в систему

## Назначение

Доработайте авторизацию школьного приложения «Кабинет классного руководителя». Страница входа открывается по маршруту `/login/`. На ней должны быть поля «Логин» и «Пароль», кнопка показа/скрытия пароля, кнопка «Войти», ссылка «Забыли пароль?» и область сообщений. После успешного входа приложение открывает стартовый раздел роли, а в боковой панели показывает данные текущего пользователя. Выход выполняется кнопкой «Выйти» в боковой панели с подтверждением.

Сайт работает без сервера: база и текущая сессия находятся в `localStorage`. После очистки хранилища и повторной загрузки восстанавливаются демонстрационные данные. Защищённые маршруты без сессии должны возвращать на страницу входа.

## Правила

- Логин перед проверкой очищается от пробелов по краям.
- Неверный пароль, неизвестный логин и пустые поля не создают сессию.
- Для неизвестного логина и неверного пароля используется одно сообщение: «Неверный логин или пароль».
- На форме пустые логин или пароль дают сообщение «Заполните логин и пароль».
- Прямой вызов `crmApi.login` с пустыми значениями должен завершаться отказом с сообщением «Заполните все поля».
- После подтверждённого выхода ключ сессии отсутствует; возврат браузера и прямой переход на `/students/` не должны раскрывать кабинет.

## Проверки

1. `test_auth_01_successful_login` — войдите под `smirnova@school.ru` / `Test#2024`. Откройте «Обзор класса» по маршруту `/overview/`; в содержимом виден текст «7Б класс (28 учеников)», форма входа отсутствует, а в боковой панели указаны «Смирнова М. В.» и «Классный руководитель».
2. `test_auth_02_password_toggle_preserves_value` — введите `Test#2024` в поле «Пароль». При первом нажатии кнопки показа поле становится видимым, при повторном — снова скрытым; в обоих состояниях введённое значение не меняется.
3. `test_auth_03_all_roles_default_screens` — по очереди войдите под всеми пятью учётными записями из таблицы. Каждая роль должна открывать ровно свой стартовый маршрут и раздел из таблицы.
4. `test_auth_04_wrong_password_rejected` — введите корректный логин классного руководителя и пароль `Wrong#2024`. На `/login/` появляется непустое сообщение об ошибке, сессия не создаётся и приложение не открывает защищённый раздел.
5. `test_auth_05_unknown_login_generic_error` — сравните результат входа с `unknown-user@school.ru` / `Wrong#2024` и с `smirnova@school.ru` / `Wrong#2024`. В обоих случаях текст ошибки в точности равен «Неверный логин или пароль».
6. `test_auth_06_empty_fields_and_whitespace` — отправьте пустую форму и форму с пустым паролем: обе показывают «Заполните логин и пароль». Затем убедитесь допустимым для этого сценария прямым вызовом `crmApi.login`, что пустые значения отвергаются с «Заполните все поля». Вход с логином `  smirnova@school.ru  ` и правильным паролем должен открыть `/overview/`; в сохранённой сессии логин хранится без пробелов.
7. `test_auth_08_logout_clears_session` — войдите классным руководителем, подтвердите выход и убедитесь, что открыта `/login/`, форма входа видима, а сессии в хранилище нет. Кнопка «Назад» и прямой адрес `/students/` также должны оставить пользователя на странице входа без восстановления сессии.
