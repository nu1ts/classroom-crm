# Classroom CRM

[Русская версия](README.ru.md)

A static single-page application for a homeroom teacher's workspace. The application models school workflows without a backend: data, authentication, and business operations are stored in the browser's `localStorage`.

## Features

The application supports five roles:

- administrator;
- homeroom teacher;
- subject teacher;
- parent;
- student.

Implemented areas include account and teacher management, academic years and directories, workload, classes and students, journals, attendance and medical certificates, schedules, parents, meetings, announcements, analytics, and weekly class monitoring.

## Technology stack

- HTML5, Tailwind CSS, and Vanilla JavaScript with ES modules;
- esbuild for application bundling;
- Playwright for end-to-end website testing;
- Python, Pytest, and Selenium in Docker for educational task verification.

## Repository structure

| Directory | Purpose |
| --- | --- |
| `src/` | SPA source code: views, routing, services, and mock data. |
| `reference/` | Built website version. Generated by the build command; do not edit manually. |
| `tests/` | Playwright specs, fixtures, page objects, helpers, and HTTP server. |
| `tasks/` | 32 educational packages with task descriptions, templates, solutions, and website variants. |
| `tools/task-mutations/` | Intentional-defect configurations for educational tasks. |
| `tools/tests-runner/` | Versioned Docker runner for Selenium/Pytest educational task verification. |
| `tools/build-task.mjs` | Builds the clean and mutated variants of an educational task. |
| `tools/verify-tasks.mjs` | npm command wrapper that builds the runner and verifies tasks. |
| `deploy/` | Dockerfile, Compose configurations, and Nginx configuration. |

## Requirements

- Node.js 20+;
- Docker Desktop for educational task verification and containerized startup;
- Python 3 only when serving the built website manually with the built-in HTTP server.

## Installation and local startup

```bash
npm ci
npm run build:site
python -m http.server 8080 -d reference
```

After startup, the website is available at `http://127.0.0.1:8080/`. Example routes: `/login/`, `/journal/`, and `/overview/`.

The build output is always written to `reference/`. After changing files in `src/`, run the following command before manual testing or E2E tests:

```bash
npm run build:site
```

## Website testing

Playwright starts `tests/server.py` automatically and serves the current build from `reference/`.

```bash
npm test
```

Run the full deterministic suite sequentially:

```bash
npm test -- --workers=1 --reporter=line
```

Additional modes:

```bash
npm run test:headed
npm run test:ui
npm run test:report
```

## Educational task verification

An educational task contains `task.md`, `template.py`, `solution.py`, a clean website in `reference/`, and `testcases/`. Each configuration in `tools/task-mutations/` defines intentional defects and the tests that must fail against them.

### Verify all tasks

```bash
npm run test:tasks
```

The command:

1. builds the local `auto-tests-runner:latest` image from `tools/tests-runner/`;
2. rebuilds the clean and mutated variants of every task;
3. runs Selenium/Pytest in Docker for each package;
4. checks that each baseline passes and each defect variant produces its expected failures.

### Verify one task

```bash
npm run test:tasks -- --task task-14-journal-attendance
```

For a quick rebuild without Docker verification, call the builder directly:

```bash
node tools/build-task.mjs --task task-14-journal-attendance
node tools/build-task.mjs --all
```

Docker-run results are temporarily stored in `tasks/<task-name>/results/`. These directories are ignored by Git and can be removed after analysis.

### Task Docker runner

`tools/tests-runner/` intentionally lives in the repository rather than only in `docs/`: the `docs/` directory is ignored by Git and would not be included in a clone or project delivery. The runner contains:

- `Dockerfile` — a Selenium Chrome-based image;
- `test.sh` — starts Selenium, an HTTP server, and Pytest for every `testcases/` variant;
- `parser.bin` — converts JUnit reports into concise JSON results.

Build the image manually when needed:

```bash
docker build -t auto-tests-runner:latest tools/tests-runner
```

## Docker startup

```bash
docker build -f deploy/Dockerfile -t classroom-crm:local .
docker run --rm -p 8080:80 classroom-crm:local
```

Check the container health endpoint:

```bash
curl http://127.0.0.1:8080/health
```

Compose configurations are located in `deploy/`.
